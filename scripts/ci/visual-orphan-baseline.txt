# Visualization Registry — accepted orphan baseline (ratchet).
#
# An orphan is a CONCEPT_VISUALS key matching no concept in any shipped
# Knowledge Graph: authored content sitting under a typo'd or stale id, so
# the renderer it names is unreachable and the concept it meant to serve
# silently falls through to a domain default or keyword matching.
#
# Every key below predates the physics production-hardening pass and belongs
# to a subject that pass was scoped away from. They are recorded here so CI
# can fail on any NEW orphan in ANY subject while these are worked off.
#
# Rules: never add a key to unblock CI — fix the mapping instead. Removing a
# key here is the goal; the validator reports stale baseline entries so this
# file can only shrink. Physics is deliberately absent: it is at zero.
#
# Generated from the registry + all six KGs; see
# scripts/validate-visualization-coverage.ts.
#
# ── Why the remaining entries are NOT mechanically fixable (orphan census) ──
# Measured with scripts/qa/orphan-census.ts. Every remaining key falls into one
# of three groups, and renaming any of them would make things worse, not better:
#
# 1. DUPLICATE ROWS. The generator they name is ALREADY reachable through a
#    real concept: cell_division via bio.cell.mitosis/meiosis, dna_structure via
#    bio.mol.dna-replication, coordinate_geometry_line via
#    math.geom.distance-formula, triangle via math.geom.triangle, vector via its
#    own live keys. Nothing is unreachable; the row is redundant.
#
# 2. REPOINTING WOULD STRIP A DEMOTION. Every real math.geom counterpart
#    (congruent-triangles, similar-triangles, area, perimeter, surface-area,
#    volume, solid-3d, line) ALREADY resolves to geometry_shape through the
#    math.geom domain default, which scopeForAsset auto-demotes. Giving it an
#    exact concept row would move it domain -> concept tier and turn an
#    honestly-demoted generic shapes card into a STRONG claim to depict the
#    concept. Same figure, worse honesty.
#
# 3. NO CONCEPT EXISTS. heights_and_distances draws applied trigonometry
#    (distance, angle of elevation) and math.trig holds only pure trigonometry.
#    math.vec and math.stat are not KG domains at all. Inventing curriculum to
#    retire an orphan is the wrong trade.
#
# Three exact-title matches are deliberately REJECTED, with reasons, so they are
# not retried: math.geom.congruence -> math.nt.congruence is a false friend
# (number-theory congruence, a === b mod n); math.trig.trigonometric-identities
# would downgrade a live geometry_shape default to a bare grid;
# cs.ds.linked-lists -> cs.struct.linked-lists covers only singly linked lists.
