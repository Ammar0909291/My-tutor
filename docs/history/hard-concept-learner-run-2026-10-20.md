# Second batch (Physics Lorentz / spacetime, Chemistry mechanisms / heterogeneous catalysis, Mathematics Green's theorem, Biology population genetics, English sociolinguistics / discourse analysis) and "fix all"

Run on the deployed app (Test8). Mean 6.0 / 10. Found: Green's theorem and heterogeneous catalysis had NO figure; reaction mechanisms and the two English concepts got a generated process flowchart; the first "show me a diagram" was answered "I don't have a picture for this one" and then a figure appeared on a later ask; two replies were stubs ("y" and one sentence; "A + B ⇌ I (fast pre-equilibrium)"); one described "the left box" of a figure that was not there; one Physics lesson closed at 33 % because the script's answer oracle missed cards.

## Root cause of "no picture, then a picture" (Vercel runtime logs, read 2026-10-20)
Not a timeout. `[visual-v2] provenance: 'no-figure:critic-reject-cached'` on the opening and `'no-figure:retry-critic-reject'` on the explicit request: the generator's figure critic judged the generated flowchart (`chem.surface.heterogeneous-cat`: "the linear flow implies poisoning occurs after regeneration, but poisoning can happen at any stage") and refused it twice. A later ask can draw a different figure that the critic passes (English sociolinguistics, turn 9). By design a refused figure is never shown; the defect was what the learner got instead, and that the concepts had no authored figure.

### Found on production after the first push of these fixes, and fixed
`eng.linguistics.language-families` (no authored figure), explicit diagram request: the learner still got "I don't have a picture for this one" followed by a fenced `World Languages ├─ Indo-European …` tree and "This tree shows …". Runtime logs of that request: the ASCII strip ran and removed the first draft's chart, then `[analogy-cap] regenerated: true` wrote a NEW reply (a tree) after every diagram strip had already run, and nothing re-checked it. Fix: a last sweep in `chat/route.ts` (the same ASCII-art and phantom-figure strips, once more on the final text, only when no figure is attached, never to an empty reply) before the no-picture judgement; the one-sentence remainder is then a stub and goes through the one regeneration in words. Pinned by `noPictureRepairWiring.test.ts`.

### Second production check and what it found (2026-10-21)
With the sweep deployed, five figure-less concepts were asked for a diagram: Chemistry spectroscopy got a clean explanation in words; language families a verbal tree description; but (a) accents-and-dialects kept "This table lets you see …" after its table was stripped, (b) applied linguistics kept "Imagine a simple flow that starts with a box labeled …", (c) the repaired spectroscopy reply carried a leaked `<!--ATTEMPT channel=…-->` annotation and an axis-tick remnant ("100 |   *"), and (d) one repair was refused with no recorded reason. Fixed: figure-talk detection widened (`isFigureTalk`: "imagine a … diagram/flow/tree/table", "box/arrow labeled/called", "this table/tree/chart … lets/shows"); `dropOrphanFigureReferences` removes a sentence that points at a table/tree/chart the reply no longer holds (never when a fenced block or markdown table is present, never to an empty reply); a regenerated reply has its internal annotation tags removed (`stripAttemptTag`, `<!--…-->`, `VISUAL:` lines) in EVERY stub repair, not only this one; a retry that tacks a question on keeps its explanation; a second, stricter attempt through the same call site; `[no-picture-repair]` logs `lastReason` (fence | short | figure-talk | ok). A regression the full suite caught in the same change: the late sweep removed true sentences about a HELD figure (`graphFigureEvidenceRoute20261011.test.ts`) — it now needs no figure attached, none held (session turns) and none shown earlier for the concept.
