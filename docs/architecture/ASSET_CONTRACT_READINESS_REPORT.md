# Asset Contract Readiness Report

**This is a REPORT, not a GATE.** `masteryReachability`'s own header already
made this decision correctly: refusing to teach a concept because it cannot
be certified would withhold real teaching from a learner over a
content-inventory problem, which is worse than the defect. This document is
the per-subject, per-(concept, band) dashboard that decision left open —
generated by `scripts/assets/contract-audit.ts`, which reads the seed corpus
on disk (not the production database — see that script's own header for the
exact difference and when it matters).

**Regenerate rather than trust this file over time**:
```
npx tsx scripts/assets/contract-audit.ts --json > /tmp/audit.json
```

## What "at contract" means

`src/lib/teaching/assetContract.ts` (v1): a taught (concept, gradeBand) pair
needs **>= 1 explanation** and **>= 3 gradeable (closed-choice) probes**.
Three is the mastery bar itself (`correctAtCheck >= 1` plus
`correctAtPractice >= 2`) with zero slack — `excludeProbeStem` never re-asks
a spent probe, so a pair holding exactly two can **never** certify a learner
who gets one question wrong, and a pair holding zero can never certify
anyone at all ("never quizzable" below).

Three subjects (chemistry, mathematics, physics) are **fully at contract** —
every taught pair can certify a learner who answers one question wrong. The
other three are not, and the shortfall has a clean shape in each case, not a
scattered one:

- **Biology and computer_science are uniformly one probe short.** Every
  single short pair in both subjects holds **exactly 2** gradeable probes
  (verified: the distinct gradeable-count value among all 108 biology short
  pairs and all 119 CS short pairs is `{2}`, not a spread). Both corpora
  (`biologySeedAssets.ts`, `csSeedAssets.ts`) were authored to a 2-probe
  standard before the contract's 3-probe floor was established, and — as of
  this session — are now wired into the production bootstrap for the first
  time (§10.1 Batch 3), so this is the first time this gap was even
  *visible* in production; before that, these two subjects had **zero**
  serving content of any kind, gradeable or not.
- **English's 410 short pairs split into two distinct buckets**: 198 pairs
  have **zero** gradeable probes at all (never quizzable, not merely short),
  212 have exactly 2. The zero-probe bucket is heavily concentrated in the
  **ADULT** band (195 of 198) — consistent with CLAUDE.md's own record that
  the English probe-contract campaign deliberately targeted native bands
  first and left ADULT as a known, flagged gap (see "English ADULT-band
  probe-contract campaign" entries, Batches 1-12, which closed 100 of the
  ~295 TRUE-gap ADULT pairs before stopping).

## What this changes about the priority order

Before this report, the working assumption (carried in several places in
CLAUDE.md) was that wiring content into production was the binding
constraint. It no longer is, for three of six subjects. The binding
constraint for biology, computer_science, and the English ADULT band is now
**content authoring** — each needs a bounded, well-defined amount of new
probe-writing, not architecture work:

- **Biology**: 108 pairs, each needs exactly 1 more gradeable probe.
- **Computer science**: 119 pairs, each needs exactly 1 more gradeable probe.
- **English**: 410 pairs; 198 need 3 probes from zero, 212 need 1 more.

None of this is a runtime defect — `resolveVisualForTurn`/`matcher.ts`/the
mastery gate all already work correctly against whatever the corpus
contains; they simply have nothing to serve for these pairs today.

## Known limits of this report

- Measures the **seed corpus on disk**, not the live database. Production
  can lag behind (the bootstrap writes a bounded slice per cold start) and
  can also hold `AI_AUTHORED` live-capture rows this script cannot see.
  Where they disagree, the database is authoritative on what *serves*; this
  report is authoritative on what is *authored*.
- The unit is (concept, band), never concept alone — a concept holding six
  probes all at one band serves zero of them to a learner at a different
  band (`matcher.ts` refuses, doesn't merely deprioritize, an adjacent-band
  match below its threshold).
- `--min 5` re-runs the same measure against the physics/chemistry
  probe-depth programme's higher target (contract-plus-two-wrong-answers);
  the default stays at the contract floor so this report keeps reporting the
  contract, not a moving target.
