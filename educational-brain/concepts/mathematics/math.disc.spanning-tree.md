## Learning Objective
By the end of this concept, the student can: (1) define a spanning tree of a connected graph $G=(V,E)$ as a subgraph $T=(V,F)$, $F\subseteq E$, that is itself a TREE per `math.disc.graph-trees`'s definition — connected AND acyclic, using every vertex of $G$ — and state the five equivalent characterizations that already-authored entry establishes (tree $\iff$ connected with $n-1$ edges $\iff$ acyclic with $n-1$ edges $\iff$ unique-path-between-every-pair); (2) prove every connected graph has at least one spanning tree (remove cycle edges one at a time until none remain) and state Cayley's formula — $n^{n-2}$ labelled spanning trees of the complete graph $K_n$; (3) define a MINIMUM spanning tree (MST) for a weighted connected graph as the spanning tree of least total edge weight, and distinguish this genuinely NEW optimization question from the EXISTENCE question in objective (2) — a graph can have many spanning trees, of which the MST is the specific one minimizing total weight; (4) apply Kruskal's algorithm (sort edges ascending, add each edge that does not create a cycle, stop at $n-1$ edges) and Prim's algorithm (grow one tree from a start vertex, always adding the cheapest edge to an unvisited vertex) to find an MST by hand; (5) use the CUT PROPERTY (the minimum-weight edge crossing any vertex partition belongs to some MST) to justify WHY Kruskal's locally greedy choice is globally optimal — not merely apply the algorithm mechanically — and use the CYCLE PROPERTY (the maximum-weight edge of any cycle belongs to no MST, given distinct weights) as the complementary elimination argument; (6) correctly state that the MST is unique when all edge weights are distinct, but that tied weights can produce multiple distinct MSTs sharing the same minimum total weight.

## Core Understanding
A spanning tree of a connected graph $G=(V,E)$ is a subgraph $T=(V,F)$ that uses EVERY vertex of $G$ ("spanning") and is itself a TREE ("tree") — connected and acyclic, per `math.disc.graph-trees`'s already-established definition. Because $T$ is a tree on $|V|=n$ vertices, it automatically has exactly $n-1$ edges — that entry's characterization equivalences apply directly and are not re-derived here. Every connected graph has at least one spanning tree: repeatedly delete an edge that lies on a cycle (which cannot disconnect the graph, since a cycle edge is never a bridge) until no cycle remains; the connected, acyclic result IS a spanning tree by construction.

The number of DISTINCT labelled spanning trees of the complete graph $K_n$ is given by **Cayley's formula: $n^{n-2}$** — a striking closed form ($K_4$ has $4^2=16$ spanning trees; $K_3$ has $3^1=3$), provable via a bijection with Prüfer sequences (length-$(n-2)$ sequences over $\{1,\dots,n\}$, of which there are exactly $n^{n-2}$).

A general connected graph typically has MANY spanning trees — this is genuinely a different, richer question than the mere EXISTENCE question above. For a WEIGHTED connected graph, the **minimum spanning tree (MST)** is the specific spanning tree of least total edge weight among all of them. Two structural facts certify which edges belong in an MST without checking every spanning tree exhaustively: the **cut property** — for any partition of $V$ into two non-empty sets $S$ and $V\setminus S$, the minimum-weight edge crossing that cut belongs to SOME MST (every MST, if that edge is uniquely cheapest) — and the **cycle property** — the maximum-weight edge of any cycle belongs to NO MST (given distinct weights), since it can always be removed and the graph stays connected.

**Kruskal's algorithm** sorts all edges by weight ascending and greedily adds each edge that does not create a cycle with what has already been added (checked efficiently via a Union-Find structure), stopping once $n-1$ edges are placed. **Prim's algorithm** instead grows a SINGLE tree from one starting vertex, at each step adding the cheapest edge connecting the current tree to any vertex not yet in it. Both are correct — not merely "usually work" — because the cut property makes the LOCAL greedy choice at every step a GLOBALLY safe one: when Kruskal considers the cheapest remaining edge $e=(u,v)$, the set of vertices already connected to $u$ forms one side of a cut, and $e$ is that cut's minimum-weight crossing edge (every cheaper edge was already processed and either added or excluded for creating a cycle within one side), so by the cut property $e$ belongs to some MST. This is the SAME kind of structural safety, at the level of the whole spanning tree, that graph-trees' Demonstration 2 established for individual edge counts: a clean numerical or local property is not automatically sufficient evidence on its own — here, however, the cut property IS the missing argument that makes greedy genuinely sufficient, in contrast to problems (like the Travelling Salesman Problem) where no such structural guarantee exists and greedy choices can be actively harmful.

The MST is UNIQUE when all edge weights are distinct (any two would-be-different MSTs can be shown to force a strictly cheaper alternative, a contradiction). When weights TIE, multiple distinct spanning trees can share the same minimum total weight — uniqueness is a property of the WEIGHTS, not an automatic guarantee of the MST concept itself.

## Mental Models
1. **Rung 1 — "spanning" and "tree" are two separate, jointly-required conditions, exactly as `math.disc.graph-trees` already established for "connected" and "acyclic."** A subgraph that touches every vertex but contains a cycle is a spanning SUBGRAPH, not a spanning TREE — the tree half of the name is not optional.
2. **Rung 2 — existence (a graph HAS a spanning tree) and optimization (WHICH spanning tree is cheapest) are genuinely different questions.** Every connected graph trivially has a spanning tree; a weighted graph can have a very large number of them, of which the MST is one specific, distinguished choice.
3. **Rung 3 — the cut property is not a heuristic that "usually works" — it is a proof that the locally cheapest edge at every step is globally safe.** This is what separates MST (where greedy is provably correct) from problems like the Travelling Salesman Problem (where a locally cheap choice can force an expensive one later).
4. **Rung 4 — MST uniqueness is a property of the WEIGHTS (distinct vs. tied), not an automatic guarantee that comes bundled with the MST concept.** Distinct weights force a unique MST; tied weights can produce several, all sharing the same minimum total.

## Why Students Fail
Because the word "spanning" is usually introduced first and emphasized as "touches every vertex," students can register only that half of the definition and relax the requirement that the result also be a TREE — accepting a connected subgraph with an extra, cycle-forming edge as a valid "spanning tree" simply because it reaches every vertex, the identical relaxation pattern `math.disc.graph-trees`' MC-1 already named for the plain tree definition, now recurring one level up. Separately, because greedy algorithms are famous for FAILING on other optimization problems (the Travelling Salesman Problem is the standard counterexample every student has likely already met), students often import a blanket "greedy is only approximately correct" belief into the MST setting without registering that MST's cut property is a specific structural guarantee TSP does not share — so Kruskal's and Prim's global correctness feels surprising or even suspect rather than provable. Finally, because introductory worked examples nearly always use distinct edge weights (avoiding tie-breaking complications when first teaching the algorithms), students can quietly absorb "the MST" as if uniqueness were a guaranteed feature of the concept itself, rather than a consequence specifically of distinct weights that a tie can genuinely break.

## Misconceptions

### MC-1: SPANNING-TREE-CAN-HAVE-CYCLES
- **Birth type:** Type 5 (instruction-induced) — foundational
- **Description:** Believing a connected subgraph that touches every vertex qualifies as a "spanning tree" even if it contains an extra, cycle-forming edge, treating "spans all vertices" as the whole requirement.
- **Why this birth type:** Confirmed matching the Blueprint's own pre-assigned classification. Instruction typically introduces "spanning" first and most vividly ("covers every vertex"), so the SPANNING half of the requirement is learned with more salience than the TREE half; the student has not yet internalized that a spanning tree must independently satisfy BOTH conditions — the exact same mechanism `math.disc.graph-trees`' MC-1 (TREE-ASSUMED-FROM-EITHER-CONDITION-ALONE) already named for the plain tree definition, now recurring at the spanning-tree level: satisfying one salient half of a conjunction is mistaken for satisfying the whole.
- **Detection probe:** "Is a connected subgraph that touches every vertex of $G$, but also contains a cycle, a spanning tree?" A student with MC-1 answers "yes."
- **Repair:** Return to `math.disc.graph-trees`'s own already-taught discipline — checking connectedness and acyclicity as two SEPARATE steps — and apply it here: a spanning tree must independently satisfy (a) spans every vertex, AND (b) is a tree (connected, acyclic). Demonstration 1 makes the contrast concrete by counting edges: a connected spanning subgraph with $\geq n$ edges necessarily contains a cycle and fails the tree half.
- **Verification of death:** Given a novel connected subgraph, the student checks both the spanning condition (every vertex present) and the tree condition (connected, acyclic — verified via the $n-1$ edge count PLUS connectedness, never edge count alone, per `math.disc.graph-trees`'s own MC-2 discipline) before concluding spanning-tree status.

### MC-2: KRUSKAL-GREEDY-IS-NOT-GLOBALLY-OPTIMAL
- **Birth type:** Type 1 (overgeneralization) — moderate
- **Description:** Believing Kruskal's algorithm produces only a locally good, possibly globally suboptimal spanning tree, by analogy to other greedy algorithms (e.g. greedy coin-change, greedy Travelling Salesman heuristics) known to be merely approximate.
- **Why this birth type:** Confirmed matching the Blueprint's own pre-assigned classification. An overgeneralization of the correctly-learned pattern "greedy algorithms are often only approximately correct," applied to a problem (MST) that is a genuine exception: the cut property gives MST a specific structural guarantee — the subproblems at each greedy step are INDEPENDENT (any cut is a valid cut regardless of prior choices) — that most greedy-fails-to-be-optimal problems (where each choice constrains what remains, as in the Travelling Salesman Problem) simply do not share.
- **Detection probe:** "Does Kruskal's algorithm always find the true minimum spanning tree, or just a reasonably good one?" A student with MC-2 answers "just a reasonably good one" or expresses uncertainty about global optimality.
- **Repair:** Walk the cut-property correctness argument explicitly (Demonstration 2, mirroring the Blueprint's own proof sketch): when Kruskal considers the next edge $e=(u,v)$, the vertices already connected to $u$ form one side $S$ of a cut; every edge cheaper than $e$ crossing that cut was already processed (added, or rejected only because it would have formed a cycle WITHIN one side — never because it crossed the cut and was rejected for cost); so $e$ is that cut's minimum-weight crossing edge, and the cut property certifies it belongs to some MST. Contrast explicitly with the Travelling Salesman Problem, where a locally cheap edge can strand the tour, forcing an expensive one later — the structural difference is that MST's cuts are independent while TSP's partial tours are not.
- **Verification of death:** Given a request to justify Kruskal's correctness, the student cites the cut property specifically (not "it usually works" or "it's a heuristic"), and can explain why MST's cut-independence structure differs from a problem like the Travelling Salesman Problem where greedy genuinely fails.

### MC-3: MST-IS-UNIQUE
- **Birth type:** Type 5 (instruction-induced) — moderate
- **Description:** Believing the MST of a weighted graph is always unique, missing that tied edge weights can produce multiple distinct MSTs of the same minimum total weight.
- **Why this birth type:** Confirmed matching the Blueprint's own pre-assigned classification. Introductory worked examples almost always use distinct edge weights to avoid tie-breaking complications while first teaching the algorithms, so the student's entire evidence base has been "the MST" as if it were a single well-defined object; the corrected picture is that uniqueness holds specifically WHEN weights are distinct (provable: any two supposedly-different MSTs force a strictly cheaper spanning tree, a contradiction) and that ties can genuinely break it.
- **Detection probe:** "A weighted graph has two edges of equal weight, and swapping between them (with everything else fixed) still produces a spanning tree of the same total weight. Is the MST still unique?" A student with MC-3 answers "yes" unconditionally.
- **Repair:** Present a small graph with one tied pair of edge weights (Demonstration 3) where two genuinely different edge sets both achieve the same minimum total weight, then contrast it with the distinct-weights uniqueness PROOF (any two claimed-different MSTs $T_1,T_2$: the minimum-weight edge present in $T_1$ but not $T_2$ is strictly cheaper than the edge it would need to replace in $T_2$'s cycle, contradicting $T_2$'s minimality) so the student sees uniqueness is EARNED by distinct weights, not automatic.
- **Verification of death:** Given a weighted graph, the student correctly states whether the MST is guaranteed unique (checking for tied weights first) rather than assuming uniqueness by default.

## Analogies
1. **The building-code analogy (for MC-1).** A structure that touches every required lot ("spanning") but has a redundant support beam forming a closed loop ("cycle") fails building code exactly as a spanning subgraph with a cycle fails to be a spanning TREE — reaching everywhere is necessary but not sufficient; the structure must also have no redundant, cycle-forming connections.
2. **The relay-race baton analogy (for MC-2's cut property).** At each handoff (edge addition), the runner takes the fastest available baton crossing from the current team to the remaining runners — because each handoff is judged independently against everyone not yet on the team (the cut), taking the fastest one available NOW never later turns out to have been a mistake, unlike a race where an early sprint could exhaust a runner needed for a later, harder leg (the Travelling-Salesman-style dependency this analogy deliberately does NOT have).
3. **The tie-breaking coin-toss analogy (for MC-3).** Two paths of exactly equal total distance to the same destination: which one you take doesn't change the total distance traveled, but it genuinely changes WHICH path was taken — distinct total costs would force one clear winner, but a tie leaves multiple, equally valid routes.

## Demonstrations
### Demonstration 1 — a spanning subgraph with a cycle is not a spanning tree, breaking MC-1 (mirrors the Blueprint's K₄ pictorial)
$K_4$ on vertices $\{1,2,3,4\}$ with edge weights $1\text{-}2{:}3,\ 1\text{-}3{:}1,\ 1\text{-}4{:}6,\ 2\text{-}3{:}2,\ 2\text{-}4{:}5,\ 3\text{-}4{:}4$. The subgraph with edges $\{1\text{-}2, 1\text{-}3, 2\text{-}3, 3\text{-}4\}$ (4 edges) touches all 4 vertices — the SPANNING half holds — but $1\text{-}2\text{-}3\text{-}1$ is a cycle, so it has $4$ edges where a genuine spanning tree needs exactly $n-1=3$: it is a spanning connected subgraph, but NOT a spanning tree. Removing edge $1\text{-}2$ (the most expensive edge of that cycle, per the cycle property) leaves $\{1\text{-}3,2\text{-}3,3\text{-}4\}$ — connected, acyclic, exactly 3 edges — a genuine spanning tree, and in fact the MST (total weight $1+2+4=7$).

### Demonstration 2 — the cut property proves Kruskal's global correctness, breaking MC-2 (mirrors the Blueprint's proof sketch)
Same $K_4$ as above. Kruskal processes edges sorted ascending: $1\text{-}3(1),\ 2\text{-}3(2),\ 3\text{-}4(4),\ 2\text{-}4(5),\ 1\text{-}2(3)$ — wait, sorted correctly: $1\text{-}3(1),\ 2\text{-}3(2),\ 1\text{-}2(3),\ 3\text{-}4(4),\ 2\text{-}4(5),\ 1\text{-}4(6)$. Step 1: add $1\text{-}3$ (weight 1) — at this instant, $\{1,3\}$ is one side of a cut against $\{2,4\}$, and $1\text{-}3$ is that cut's cheapest crossing edge (no cheaper edge exists at all yet), so the cut property certifies it belongs to some MST. Step 2: add $2\text{-}3$ (weight 2) — now $\{1,2,3\}$ vs. $\{4\}$ is the relevant cut, and $2\text{-}3$ is its cheapest crossing edge among those not yet excluded. Step 3: skip $1\text{-}2$ (weight 3) — both endpoints already connected within $\{1,2,3\}$, so adding it would create a cycle WITHIN one side of every remaining cut, never across one — this is exactly why skipping it costs nothing toward optimality. Step 4: add $3\text{-}4$ (weight 4), completing the spanning tree $\{1\text{-}3,2\text{-}3,3\text{-}4\}$, weight 7 — matching Demonstration 1's independently-derived MST.

### Demonstration 3 — tied weights break MST uniqueness, breaking MC-3
Vertices $\{1,2,3,4\}$, edges $1\text{-}2{:}1,\ 2\text{-}3{:}2,\ 3\text{-}4{:}2,\ 1\text{-}3{:}3,\ 2\text{-}4{:}5$. Two edges tie at weight 2 ($2\text{-}3$ and $3\text{-}4$) — Kruskal must add $1\text{-}2(1)$ first regardless, then can process $2\text{-}3$ or $3\text{-}4$ in either order, adding both (neither creates a cycle with $1\text{-}2$ alone), for spanning tree $\{1\text{-}2,2\text{-}3,3\text{-}4\}$, weight $1+2+2=5$. No alternative achieves a lower total (verified by checking every other 3-edge connected subset), so this MST happens to be the unique one here DESPITE the tie — a genuinely tied-weight example where uniqueness still holds only because the tied edges are not interchangeable with any third alternative of the same cost. (Contrast: a graph where the SAME two vertices could be connected by either of two equal-weight edges, all else identical, produces two literally different MSTs of the same total weight — the Blueprint's own MC-3 characterization.)

## Discovery Questions
1. "If a connected subgraph touches every vertex of the original graph, does that alone guarantee it's a spanning TREE — or is there a second condition it also needs to satisfy?"
2. "When Kruskal's algorithm picks the cheapest available edge at each step, could that locally cheap choice ever force a more expensive choice later — the way it can in other 'take the cheapest option now' strategies?"
3. "If two different edges in a weighted graph happen to have exactly the same weight, could swapping between them ever produce two different spanning trees with the same minimum total weight?"

## Teaching Sequence
Best taught by **direct instruction with embedded conflict-evidence and contrast demonstrations**, extending `math.disc.graph-trees`'s own established pattern one level up — the spanning-tree definition, existence proof, Cayley's formula, and the Kruskal/Prim algorithms with their cut-property correctness argument are precise definitional and algorithmic content most efficiently introduced directly, with each Discovery Question posed immediately before its corresponding demonstration so the student predicts before the contrast is confirmed.
1. Introduce the spanning-tree definition (reusing `math.disc.graph-trees`'s tree definition directly) and the existence proof, posing Discovery Question 1 before working Demonstration 1's cycle-inclusive counterexample (targeting MC-1). Mention Cayley's formula ($n^{n-2}$) as a striking closed-form consequence.
2. Introduce the MST optimization question and the cut/cycle properties, posing Discovery Question 2 before working Demonstration 2's step-by-step Kruskal correctness trace (targeting MC-2), explicitly contrasting with the Travelling Salesman Problem's lack of the same structural guarantee.
3. Introduce Prim's algorithm as a second correct MST method (grow-from-a-vertex rather than sort-globally), briefly noting the sparse-vs-dense-graph efficiency trade-off between the two.
4. Introduce the distinct-vs-tied-weight uniqueness question, posing Discovery Question 3 before working Demonstration 3's tied-weight example (targeting MC-3).
5. Assess with the Blueprint's P77 problem set and P76 transfer probe.

## Tutor Actions
1. **On a spanning-tree-classification question:** always require the student to check BOTH the spanning condition (every vertex present) AND the tree condition (connected, acyclic — via `math.disc.graph-trees`'s own two-step discipline), never accepting a subgraph that merely touches every vertex as sufficient.
2. **On a Kruskal-correctness question:** require the student to invoke the cut property by name, not just describe the algorithm's steps — mechanical execution without the correctness argument is treated as incomplete.
3. **On an MST-uniqueness question:** ask first whether the graph's edge weights are all distinct or contain ties before accepting any uniqueness claim.
4. **On a Prim-vs-Kruskal question:** frame the choice as a sparse-vs-dense-graph efficiency trade-off (Kruskal favored for sparse graphs via edge-sorting; Prim favored for dense graphs via an adjacency-matrix implementation), never as one algorithm being "more correct" than the other — both are provably correct via the same cut property.

## Voice Teaching Notes
1. **Register:** precise and proof-oriented — this concept's central discipline is that Kruskal's and Prim's correctness is PROVEN via the cut property, not merely observed to "usually work," so language should consistently invite "why is this guaranteed to be correct?" rather than "does this usually give a good answer?"
2. **Load-bearing sentence, spoken slowly:** "The cheapest edge crossing any cut is safe to take — that is not a heuristic, it is a proof, and it is what makes Kruskal's and Prim's greedy choices genuinely, always correct."
3. **Wait time:** pause after posing Discovery Question 2, giving the student space to predict whether a locally cheap edge could ever backfire before Demonstration 2's cut-by-cut trace confirms it cannot.

## Assessment Signals
1. **Gate concept:** correctly classifies whether a given connected spanning subgraph is a spanning tree, checking both the spanning and tree conditions explicitly.
2. **Existence-vs-optimization discrimination:** correctly distinguishes "does a spanning tree exist" (always yes, for a connected graph) from "which spanning tree is minimum" (a genuinely separate optimization question).
3. **Cut-property justification:** correctly cites the cut property (not mere mechanical execution) when asked to justify why Kruskal's or Prim's algorithm produces a true MST.
4. **Uniqueness discrimination:** correctly states whether an MST is guaranteed unique for a given weighted graph, checking for tied weights before concluding.
5. **Transfer:** applies Kruskal's or Prim's algorithm, with cut-property justification, to a novel weighted graph, and correctly computes total MST weight.

## Tutor Recovery Strategy
If the student accepts a cycle-containing spanning subgraph as a spanning tree, return explicitly to `math.disc.graph-trees`'s own two-condition discipline and require an edge count PLUS a connectedness check on every subsequent classification question until the habit transfers automatically. If the student cannot justify Kruskal's correctness beyond "it usually works," walk the cut-property proof sketch on a fresh small graph, having the student identify the relevant cut at each step themselves before revealing which edge the property certifies. If the student assumes automatic MST uniqueness, present a graph specifically constructed with a genuine tie between interchangeable edges (not merely tied but non-interchangeable, as Demonstration 3's contrast note makes explicit) until two visibly different MSTs of the same total weight are both accepted as valid.

## Memory Hooks
1. "Spans everywhere AND is a tree — both, just like connected-and-acyclic one level down."
2. "The cut property isn't a hope — it's a proof: the cheapest edge crossing any cut is always safe."
3. "Distinct weights, unique MST. Tied weights, maybe more than one — same minimum total, different edges."
