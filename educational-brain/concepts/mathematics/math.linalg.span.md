## Learning Objective
Compute $\mathrm{span}(S)$ for a small set of vectors $S$ as the set of ALL linear combinations
$c_1v_1+\cdots+c_kv_k$ (every choice of scalars, never a sample of combinations); correctly
determine whether a target vector lies in $\mathrm{span}(S)$ by SOLVING the linear system for
the combination coefficients, never by inspection; and correctly recognize that adding a
REDUNDANT vector (already a combination of the existing ones) to $S$ does not enlarge the span.

## Core Understanding
$\mathrm{SPAN}(S)$ IS THE SET OF ALL LINEAR COMBINATIONS, NOT THE GENERATING SET ITSELF:
$\mathrm{span}(S)=\{c_1v_1+c_2v_2+\cdots+c_kv_k:c_1,\ldots,c_k\in\mathbb R\}$ — the set of every
combination reachable using EVERY possible choice of scalars, reusing `math.linalg.subspace`'s
own definition directly: $\mathrm{span}(S)$ is the SMALLEST subspace containing $S$. A generating
set $S$ may have just 2 elements, while $\mathrm{span}(S)$ is typically VASTLY larger — often
infinite (e.g. all of $\mathbb R^2$ from two non-parallel vectors).

MEMBERSHIP IS SETTLED BY SOLVING, NEVER BY INSPECTION: whether a target vector $w$ lies in
$\mathrm{span}(S)$ is determined by actually SOLVING the linear system
$c_1v_1+\cdots+c_kv_k=w$ for the coefficients $c_i$ — a target can look "unrelated" to $S$'s
vectors on casual inspection yet genuinely be in the span (or vice versa), and only an explicit
solve-and-verify settles it reliably.

REDUNDANCY DOES NOT ENLARGE THE SPAN: adding a vector to a spanning set $S$ enlarges
$\mathrm{span}(S)$ ONLY IF that vector was NOT already reachable from $S$'s existing vectors — a
REDUNDANT addition (already a linear combination of $S$'s vectors) changes $\mathrm{span}(S)$
not at all, regardless of how many vectors are added. Whether a new vector helps depends entirely
on whether it introduces a genuinely NEW direction, verified by the same explicit-solve
discipline as membership checking.

## Mental Models
- **"$\mathrm{span}(S)$ is everything REACHABLE from $S$ by combination — not the small list $S$
  itself, which is just the starting ingredients."**
- **"Whether a vector is 'in the span' or 'enlarges the span' is a SOLVE, never a guess — set up
  the system and check."**

## Why Students Fail

### MC-1: SPAN-EQUALS-GENERATING-SET
- **Surface form**: treats $\mathrm{span}(S)$ as if it were just the (finite) set $S$ itself,
  rather than the (typically infinite) set of ALL linear combinations of $S$.
- **Birth type**: Type 3, language contamination (identified in the Blueprint as the
  FOUNDATIONAL misconception — the everyday reading of "span of S" as "the things in S" collides
  with the technical meaning "everything generated by S," a basic category error that
  undermines every subsequent computation).
- **Repair**: re-demonstrate that EVERY choice of scalars reaches a distinct point, making the
  size gap between $S$ and $\mathrm{span}(S)$ vivid before any abstract notation is introduced.

### MC-2: SPAN-MEMBERSHIP-BY-INSPECTION
- **Surface form**: judges whether a vector is in $\mathrm{span}(S)$ by eyeballing or trying a
  couple of sample combinations, rather than setting up and solving the linear system.
- **Birth type**: Type 5, instruction-induced (many introductory examples use "obviously related"
  vectors where the coefficients are visually apparent, so the discipline of an explicit solve
  is never forced until a genuinely non-obvious target appears).
- **Repair**: re-set up and solve the linear system explicitly for the specific target vector in
  question.

### MC-3: EVERY-NEW-VECTOR-ENLARGES-SPAN
- **Surface form**: assumes adding any vector to a spanning set $S$ always produces a strictly
  larger span, missing that a REDUNDANT vector changes nothing.
- **Birth type**: Type 1, overgeneralization (a general "more inputs, more output" intuition is
  over-applied to span, where a redundant addition contributes nothing new).
- **Repair**: re-check whether the added vector is ALREADY a combination of the existing
  generators via an explicit solve, distinguishing redundant additions from genuinely new
  directions.

## Analogies
- **"$S$ is the recipe's listed ingredients; $\mathrm{span}(S)$ is every dish those ingredients
  can possibly combine to make — a vastly larger set than the ingredient list itself."**
- **Anti-analogy**: adding MORE generators does NOT automatically mean a BIGGER span — a
  redundant ingredient that duplicates what's already achievable changes nothing about what can
  be made.

## Demonstrations
- **Demonstration 1 (targets MC-1)**: for $v_1=(1,0),v_2=(0,1)$ in $\mathbb R^2$, ANY target
  point $(a,b)$ is reached exactly by $a\cdot v_1+b\cdot v_2=(a,b)$ — so
  $\mathrm{span}(\{v_1,v_2\})=\mathbb R^2$, the ENTIRE plane, not just the two listed vectors.
- **Demonstration 2 (targets MC-2)**: is $w=(7,5)$ in $\mathrm{span}(\{(1,2),(3,1)\})$? Solving
  $c_1(1,2)+c_2(3,1)=(7,5)$ gives $c_1=8/5,c_2=9/5$, verified by direct substitution — an
  inspection-only guess ("7 and 5 don't obviously relate") gives no reliable answer; only the
  explicit solve confirms membership.
- **Demonstration 3 (targets MC-3)**: starting from $S_1=\{(1,0),(0,1)\}$ (span $=\mathbb R^2$),
  adding $(2,3)=2(1,0)+3(0,1)$ (ALREADY a combination) leaves the span completely UNCHANGED.
  Contrast: starting from $S_3=\{(1,0)\}$ (span = the x-axis) and adding $(0,1)$ (NOT a multiple
  of $(1,0)$) genuinely enlarges the span to all of $\mathbb R^2$.

## Discovery Questions
1. "If $S=\{(1,0),(0,1)\}$, is $\mathrm{span}(S)$ just those two points, or something much
   larger?"
2. "Can you tell whether $(7,5)$ is in $\mathrm{span}(\{(1,2),(3,1)\})$ just by looking, or do you
   need to solve something?"
3. "If a spanning set already reaches every vector in the plane, does adding a THIRD vector
   always make the span bigger?"

## Teaching Sequence
1. **Anchor**: connect to `math.linalg.subspace`'s own definition of $\mathrm{span}(S)$ as the
   smallest subspace containing $S$, and its already-mastered 3-condition subspace test.
2. **Representation shift**: Demonstration 1's "every point is reachable" build, isolating MC-1
   by making the size gap between $S$ and $\mathrm{span}(S)$ vivid.
3. **Contrast pair**: Demonstration 2's explicit solve-and-verify versus inspection-only
   guessing, isolating MC-2.
4. **Contrast pair**: Demonstration 3's redundant-vs-genuinely-new addition, isolating MC-3.
5. **Mastery gate**: require a correct description of $\mathrm{span}(S)$ for a new generating
   set, a correct membership determination via an explicit solve, and a correct redundancy
   judgment for a new addition, at the Blueprint's own stated MAMR of 5/5 (⌈0.9×5⌉).

## Tutor Actions
- Never accept $\mathrm{span}(S)$ described as merely "the vectors in $S$" — require the full
  set-of-all-combinations description.
- Never accept a membership or redundancy judgment without an explicit solved system shown.

## Voice Teaching Notes
- Say "is that the generating set, or everything it can reach?" whenever $\mathrm{span}(S)$ is
  discussed.
- When membership is claimed, ask "did you solve that, or estimate it?"

## Assessment Signals
- **Rung 1 (recognition)**: learner correctly describes $\mathrm{span}(S)$ as the set of all
  linear combinations, distinguishing it from $S$ itself.
- **Rung 2 (application)**: learner correctly determines span membership for a specific target
  vector via an explicit solved linear system.
- **Rung 3 (transfer)**: learner correctly determines, for a NEW applied scenario (e.g. mixing
  base concentrates), whether adding a new generator is redundant or genuinely expands what is
  reachable.

## Tutor Recovery Strategy
- If MC-1 recurs, re-demonstrate the "every point reachable" build for a fresh generating set.
- If MC-2 recurs, re-solve the specific target vector's membership system explicitly.
- If MC-3 recurs, re-check the specific added vector's redundancy via an explicit solve.

## Memory Hooks
- "Span is everything reachable — not just the listed vectors."
- "Solve for membership — never guess by eye."
- "A redundant vector changes nothing; only a genuinely new direction grows the span."
