## Learning Objective
The student will state the correct solvability criterion for ax+by=c (integer solutions exist if and only if gcd(a,b) divides c, not only when c equals gcd(a,b) exactly), correctly generate the full infinite family of integer solutions using the proper step size, and correctly scale Bézout's Identity's coefficients when c is a multiple of, but not equal to, gcd(a,b).

## Core Understanding
A linear Diophantine equation ax+by=c has integer solutions if and only if gcd(a,b) divides c — a genuine generalization of Bézout's Identity (which only guarantees a solution for the specific case c=gcd(a,b)). When solvable, the equation has INFINITELY many integer solutions, not just one: given one solution (x0,y0), every pair (x0+k·b/gcd(a,b), y0−k·a/gcd(a,b)) for any integer k is also a solution — and this specific step size (b/gcd(a,b) for x, a/gcd(a,b) for y) is the only one that preserves the equation; arbitrary adjustments to x and y do not. To construct a solution when c≠gcd(a,b) (but gcd(a,b) divides c), take Bézout's Identity's coefficients x0,y0 (satisfying ax0+by0=gcd(a,b)) and SCALE both by c/gcd(a,b): x=x0·(c/gcd(a,b)), y=y0·(c/gcd(a,b)) then satisfies ax+by=c directly — this scaling step is necessary and is not automatic from Bézout's Identity alone.

## Mental Models
1. **The divides-not-equals model**: the solvability condition is gcd(a,b) DIVIDES c — a broader condition than requiring c to equal gcd(a,b) exactly.
2. **The correct-step-size model**: the infinite solution family moves by specific steps (b/gcd(a,b) in x, a/gcd(a,b) in y) — not by arbitrary increments.
3. **The scale-after-Bézout model**: Bézout's Identity gives a solution for c=gcd(a,b); reaching a general solvable c requires an explicit scaling step by c/gcd(a,b), not direct reuse of the unscaled coefficients.

## Why Students Fail
The foundational failure is restricting the solvability criterion to c=gcd(a,b) exactly, overgeneralizing from Bézout's Identity's own special-case statement rather than recognizing the broader divides condition. A second failure is believing the infinite solution family can be generated by adding any arbitrary integer to x (and adjusting y arbitrarily), missing that only the specific step sizes b/gcd(a,b) and a/gcd(a,b) preserve the equation. A third failure is directly reusing Bézout's Identity's unscaled coefficients as a solution when c≠gcd(a,b), omitting the required scaling step by c/gcd(a,b).

## Misconceptions
Authored directly via the birth-taxonomy diagnostic procedure (no Blueprint exists for this concept):

- **LINEAR-DIOPHANTINE-SOLVABILITY-CRITERION-MISAPPLIED-AS-C-EQUALS-GCD** (FOUNDATIONAL)
  - **Description**: believing ax+by=c has integer solutions only when c EQUALS gcd(a,b) exactly, rather than the correct condition that gcd(a,b) DIVIDES c.
  - **Birth type**: Type 1, overgeneralization — Bézout's Identity specifically produces x,y for the case c=gcd(a,b), and this special case is over-applied as if it defined the entire solvability criterion.
  - **Repair approach**: verify directly that 2x+4y=6 has solutions (gcd(2,4)=2 divides 6, even though 6≠2), then confirm 2x+4y=5 has none (gcd(2,4)=2 does not divide 5), establishing the divides condition as genuinely broader than equality.

- **LINEAR-DIOPHANTINE-PARAMETRIZATION-STEP-SIZE-MISCOMPUTED** (Foundational)
  - **Description**: believing an arbitrary integer can be added to x (with any corresponding adjustment to y) and still preserve a solution, rather than recognizing the specific required step sizes b/gcd(a,b) for x and a/gcd(a,b) for y.
  - **Birth type**: Type 6, analogy overextension — carrying over the general "infinitely many solutions exist" idea from `math.nt.extended-euclidean-algorithm`'s own non-uniqueness finding, without the additional constraint on step size specific to generating the complete solution family here.
  - **Repair approach**: verify directly that adding an arbitrary (non-step-sized) amount to x breaks the equation, then confirm adding exactly b/gcd(a,b) (with the matching subtraction from y) preserves it.

- **LINEAR-DIOPHANTINE-SOLVED-VIA-BEZOUT-DIRECTLY-WITHOUT-SCALING-WHEN-C-NEQ-GCD** (Moderate)
  - **Description**: directly reusing Bézout's Identity's unscaled x,y coefficients (found for ax+by=gcd(a,b)) as a solution to ax+by=c when c≠gcd(a,b), omitting the required scaling step.
  - **Birth type**: Type 5, instruction-induced — Bézout's Identity's construction procedure is taught and practiced specifically for the c=gcd(a,b) case, and the additional scaling step needed for a general solvable c is easy to omit when the procedure is applied to a superficially similar but distinct target equation.
  - **Repair approach**: work a full example where c=3×gcd(a,b), explicitly scaling Bézout's coefficients by 3 before verifying the result satisfies the original equation.

## Analogies
- **The divides-versus-equals framing**: the solvability test is like asking "does c fit evenly into the gcd's multiplication table?" — a broader question than "is c exactly the gcd?"

## Demonstrations
- Verifying 2x+4y=6 has solutions (gcd divides c) while 2x+4y=5 does not (gcd does not divide c), refuting the equals-only misconception.
- Generating the correct infinite solution family for a solved equation using the proper step size, contrasted against an arbitrary (incorrect) increment.
- Scaling Bézout's Identity's coefficients by c/gcd(a,b) to solve a target equation where c is a multiple of, but not equal to, the gcd.

## Discovery Questions
1. "Does ax+by=c need c to equal the gcd exactly, or just to be a multiple of it?"
2. "If you found one solution, can you get another one by adding any number you like to x?"
3. "Can you use Bézout's Identity's x,y directly when c isn't the gcd itself?"

## Teaching Sequence
1. Establish the divides-not-equals solvability criterion with a direct contrast (solvable vs. unsolvable case).
2. Verify the correct step size for generating the infinite solution family, contrasted against an arbitrary increment that fails.
3. Work a full scaling example: Bézout's coefficients scaled by c/gcd(a,b) to solve a general solvable equation.
4. Mastery gate: determine solvability, construct one solution via scaling, and generate a second solution via the correct step size.

## Tutor Actions
- **TEST-THINKING: Error Analysis** — contrasting a solvable equation (gcd divides c) against an unsolvable one (gcd does not divide c).
- **DO: Worked Example** — generating the infinite solution family using the correct step size, contrasted against an arbitrary increment.
- **DO: Worked Example** — scaling Bézout's Identity's coefficients by c/gcd(a,b) to solve a general equation.
- **TELL: Explanation** — the three-part method: check divisibility, scale Bézout's coefficients, generate further solutions by the correct step.

## Voice Teaching Notes
Before accepting any claimed solution to ax+by=c, ask "did you check that gcd(a,b) divides c first?" as a standing verbal gate directly targeting the solvability-criterion misconception.

## Assessment Signals
- **Transfer probe (independence mode — no cross-link listed in the KG for this concept)**: "A student claims 3x+9y=10 has integer solutions because gcd(3,9)=3 and 10 is 'close enough' to 3. Explain precisely why this equation has NO integer solutions, using the exact divisibility criterion."
- **Mastery gate (4-item problem set)**: (1) determine whether 6x+15y=9 has solutions and justify; (2) if solvable, construct one solution by scaling Bézout's Identity's coefficients; (3) generate a second, different solution using the correct step size; (4) explain why an arbitrary (non-step-sized) adjustment to x would break the equation. MAMR 4/5.

## Tutor Recovery Strategy
If the equals-only misconception persists, require the student to test the divisibility condition explicitly (compute gcd(a,b), check whether it divides c) on three different equations — some solvable, some not — before accepting any claim about whether a given equation has solutions.

## Memory Hooks
- "Solvable means gcd(a,b) divides c — not that c IS the gcd."
- "The step size for more solutions is b/gcd and a/gcd — not any number you like."
- "When c isn't the gcd itself, scale Bézout's x,y by c/gcd first."
